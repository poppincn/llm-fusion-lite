Era Fusion — how the flow actually works

One request → a panel of models → an influence-weighted judge that synthesizes (does not just pick) → a learned-over-time answer. v0.1

The short version: it is not "all three answer and the judge picks the best." The judge writes a brand-new answer built from the strongest correct material across every panelist — resolving their disagreements, keeping insights only one model had, and filling gaps none covered well. Selection is the floor; we do generative synthesis.

The pipeline

1 Request
The user's prompt (chat, CLI, OpenAI-compatible endpoint, or the /fuse skill).
▼
2 Adjudicate fast model
A cheap classifier reads the request and decides the subject (coding, math, research…) and the depth it deserves: light (one shot) · standard (+ web search) · deep (agentic: web + tools).
▼
3 Select panel adaptive
Picks the strongest models for this subject using learned per-subject expertise (SME), with ε-greedy exploration so under-tried models still get a shot. Distinct models per scope.
▼
4  Panel fan-out — the same prompt to every model, in parallel, each answering independently (diversity is harvested, not scripted)

PHASE B · GENERATIVE SYNTHESIS  (streamed)
Writes the single best answer, grounded in Phase A: resolve each contradiction toward the better-supported claim, incorporate the correct unique insights, fix the gaps. The output is a new composition — often better than any individual answer, not a copy of one.

Returned to the user (streamed). The run — panel responses, influence scores, usage — is persisted.
↻ Learn: the judge's influence scores accumulate into per-model, per-subject expertise (SME); optional 👍/👎 refines it. Next time the same subject comes up, step 3 fields a stronger panel and step 5 carries a better prior. This is what Sakana Fugu and OpenRouter Fusion don't do at inference.

"Isn't it just: three answers → judge picks one?" — No.

❌ Selection (what people assume)

Rank the 3 answers, return the top one verbatim. Capped at the best single answer present. If every model missed one piece, the final answer misses it too.

✅ Synthesis (what we do)

A new answer assembled from the best parts of all of them, with disagreements resolved and gaps filled. Can exceed every individual answer. Evidence: on GPQA-Diamond items where Opus-as-judge answered wrong on its own, fusion still answered right — it deferred to the better-supported panelists rather than to itself.

Can we be more optimal? Yes — the research landscape

We're currently a solid single-layer generative fusion (the MoA "aggregator" / LLM-Blender "GenFuser" family). The documented gains come from iteration, ranking, and verification on top.

Proposed roadmap for llm-fusion-lite

Wire these to the existing depth tiers so cost scales with what the question deserves:

  • standard — keep today's flow (fan-out → analyze → synthesize). Already strong.
  • deep — add one MoA refinement layer (panelists see each other's first answers and revise) + a verification pass (execute code / recheck math / consistency). Biggest expected quality lift.
  • cross-cutting — add a debate round on detected contradictions only (cheap, targets exactly where models disagree) and confidence weighting in the judge prior.
  • measure it — every change goes through scripts/bench/run.mjs (GPQA-Diamond, objective grading) so "more optimal" is proven, not assumed — comparing fusion vs best/avg single and vs judge-solo.
